# Offline JSON asset registry

## Repository audit baseline

At baseline commit `556eb679584fe0a89043c57849680d7785f6589a`, the tracked tree contained 154 files and exactly one `.json`: `abi/afcore.abi.json`. It is generated by `tools/abi_manifest.py` and describes the C ABI, not character/material assets. The native `af_json` parser is used by the GLB importer. The status document says the newer GLB reader, parser, scene and profiler sources were not reachable from the JNI surface in the recorded APK.

## Runtime layout

The SDK registry reads `files/avatarforge/manifest.json`; referenced data files are under `files/avatarforge/assets/`. It is offline-only and demand-loaded, not scanned or preloaded at startup. Manifest and individual JSON reads are capped at 2 MiB. It rejects duplicate IDs, missing dependencies, dependency cycles, absolute/path-traversal paths, unsupported asset types, unknown fields and invalid character-preset values.

## Manifest example

```json
{
  "schemaVersion": 1,
  "assets": [
    {
      "id": "character-redhair-v1",
      "type": "character_preset",
      "path": "presets/character-redhair-v1.json",
      "version": 1,
      "dependencies": [],
      "license": "record actual licence",
      "source": "record actual source"
    }
  ]
}
```

This is a format example, not a shipped character asset.

## Real runtime connection and limits

`AssetRegistry.loadCharacterPreset(id)` converts a validated `character_preset` JSON to the same typed `AvatarSpec` used by the existing native generator. That category is connected to generation at the SDK boundary. Other types (materials, skeletons, animations, blendshapes, procedural parameter packs, renderer settings and reference metadata) are indexed, but **not** yet connected to rendering/rigging/geometry by this change. A manifest entry alone does not make them work.

The current repository does not contain a large JSON asset collection. The registry does not import Dropbox content automatically; files must be copied into app-private storage by a future explicit import flow, preserving provenance and licences.
